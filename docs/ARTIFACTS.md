# Artifacts

Run artifacts are provenance-aware outputs. JSON artifacts use a common envelope:

```json
{
  "metadata": {
    "artifact_type": "...",
    "artifact_schema_version": "1.0",
    "generator": "...",
    "created_at": "...",
    "run_id": "...",
    "artifact_id": "...",
    "dataset_name": "...",
    "task_mode": "...",
    "input_resources": [],
    "input_artifacts": [],
    "configuration": {},
    "software_version": {},
    "determinism": {}
  },
  "data": {}
}
```

Resources are external or snapshotted inputs, such as dataset paths, task
profiles, threshold YAML, and decision-policy YAML. Artifacts are generated
outputs that cite those resources and upstream artifacts by provenance.

## Core Run Artifacts

### `validated_run_context.json`

Generated after configuration validation by `ValidatedRunContextAgent`. It
freezes resolved dataset resources, paths, task-profile identity, deterministic
threshold values, calibration source, expected artifacts, and known case IDs.

### `dataset_validation.json`

Generated by `ValidationAgent`. It checks raw resources and each task profile's
required segmentations. Missing required inputs can mark a case invalid and set
`omit_from_training` as hard evidence; that internal evidence label is not a
canonical final action.

### `summary.json`

Generated by `SummaryAgent`. It is the central per-case measurement artifact,
including image and mask geometry, volumes, overlap and FOV evidence, HU
statistics, metadata, target presence, and case status.

### `thresholds.calibrated.yaml` and `threshold_calibration.json`

Calibration is run-scoped by default. The YAML is the calibrated threshold
resource used by calibrated QC. `threshold_calibration.json` records clean
reference selection, exclusions, task-profile calibratable domains,
source-summary provenance, and whether values changed. Calibration and both QC
passes consume the run-local `summary.json`. Reused calibrated thresholds must
match the summary content and task mode recorded in their metadata.

### `qc_report_deterministic.json`

Generated by `DeterministicQCAgent` from `summary.json`, the selected task
profile, and fixed `configs/thresholds.yaml`. It is deterministic evidence, not
the final decision artifact.

### `qc_report_calibrated.json`

Generated by `CalibratedQCAgent` from the same summary and task profile using the
run-scoped calibrated thresholds. Calibration cannot override hard failures.

### `qc_comparison.json`

Generated by `QCComparisonAgent`. It aligns deterministic and calibrated cases
and records recommendation, risk, score, and driving-domain changes. The
orchestrator also writes `qc_comparison.csv` and
`calibration_impact_report.txt`.

### `reasoning_artifact.json`

Generated by `ReasoningAgent` from validated context, both evidence variants,
and their comparison. It summarizes cited evidence, conflicts, uncertainty, and
limitations. Its schema forbids decision, action, and routing authority.

### `medical_critique.json`

Generated by `MedicalCriticAgent`. It checks structured reasoning claims against
cited evidence for grounding and internal consistency. It is explicitly
`binding: false`, does not inspect images, and is not an input to routing or
final policy execution.

### `review_routing.json`

Generated by `ReviewRoutingAgent` from validation, deterministic evidence,
calibrated evidence, and comparison only. It deterministically routes uncertain
non-hard-failure cases. Hard failures and missing evidence are not placed in the
manual review queue.

### `decision_policy.yaml`

An immutable input-resource snapshot created for orchestrated `pancreas_only`
runs. It is copied from `configs/policies/visible_pancreas_v1.yaml`; the final
artifact records its resource hash, policy ID, version, and matched rule. It is
not currently created for the two lesion task modes.

### `final_qc_decisions.json`

Generated by `FinalDecisionAgent`. It is the case-level source of truth and uses
only `keep`, `warning`, `review`, `reject`, or `insufficient_evidence`. For
`pancreas_only`, policy evaluation uses only validation, deterministic evidence,
calibrated evidence, comparison, and routing. Reasoning and critique cannot
enter the policy context.

### `eval_report.json`

Generated post hoc by `EvaluationAgent`. It audits supplied artifacts without
changing or re-deriving final decisions. It reports artifact integrity, evidence
stability, explanation validity, routing consistency, policy safety, task
consistency, calibration impact, and explicit external-validation limitations.
Golden-label agreement is included only when a golden-label artifact is supplied.

### `execution_graph.json`

Generated by `OrchestratorAgent` after successful execution. It records ordered
steps, explicit dependencies, outputs, run identity, dataset, and task mode.

## Golden Review Artifacts

`build_golden_review_package.py` creates a blinded reviewer package and a
separate administrative `system_reference.csv`. The reviewer receives only
`review_manifest.csv` and `REVIEW_PROTOCOL.md`. `import_golden_review.py`
validates the completed package and writes `golden_labels.json` with package and
source-artifact provenance.
